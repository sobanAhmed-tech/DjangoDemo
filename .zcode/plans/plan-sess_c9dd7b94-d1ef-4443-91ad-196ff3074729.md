# Instagram-style Clone — Build Plan

Transform the Django Blog API into an Instagram-like social app. **No image uploads** (per your choice), so posts stay text-based and avatars are auto-generated initials/colored circles — no Pillow or media config needed.

**Non-destructive:** all changes are additive (new tables + new fields). Existing users/posts/comments are preserved. No database reset.

## 2. Backend — `accounts` app (new)

### Models (`accounts/models.py`)
- **Profile** (OneToOne→User, auto-created on signup via signal + data migration for existing users):
  - `bio` (TextField, blank)
  - `allow_likes_from` = `everyone` | `friends` | `nobody` (default `everyone`)
  - `allow_comments_from` = `everyone` | `friends` | `nobody` (default `everyone`)
- **Follow** (directional): `follower`→User, `following`→User, `created_at`, `unique_together`, blocks self-follow.
  - *Friends* = mutual follow (A→B and B→A). *Mutual friends* computed from this.
- **Notification**: `recipient`→User, `actor`→User, `verb` (text), `post`→Post(nullable), `read`(bool), `created_at`. Created when someone likes/comments/follows.

### Endpoints (mounted at `/api/`)
| Method | Path | Purpose |
|---|---|---|
| GET | `/api/users/?search=` | search/list users with stats + `is_following` |
| GET | `/api/users/suggested/` | users not yet followed (ranked by mutuals) |
| GET | `/api/users/<id>/` | profile + post/follower/following counts |
| GET/PATCH | `/api/profile/me/` | view/edit own profile & privacy settings |
| POST/DELETE | `/api/users/<id>/follow/` | follow / unfollow |
| GET | `/api/users/<id>/followers/` | follower list |
| GET | `/api/users/<id>/following/` | following list |
| GET | `/api/users/<id>/mutual-friends/` | mutual friends list |
| GET | `/api/notifications/` | my notifications (paginated) |
| POST | `/api/notifications/read/` | mark all as read |

## 3. Backend — `blog` app (extended)

### Models (`blog/models.py`) — additive
- **Like**: `user`→User, `post`→Post, `unique_together` (one like per user per post).
- **SavedPost** (bookmark): `user`→User, `post`→Post, `unique_together`.
- `Post` and `Comment` unchanged.

### Richer serializers
- **PostSerializer** now also returns: `author_username`, `author_bio`, `like_count`, `comment_count`, `is_liked`, `is_saved`, `is_following_author`.
- **CommentSerializer** now also returns `author_username`.

### New/updated endpoints (mounted at `/api/`)
| Method | Path | Purpose |
|---|---|---|
| GET | `/api/feed/` | posts from me + people I follow (Home feed) |
| GET | `/api/posts/` | all posts (Explore) — now with like/save counts |
| POST/DELETE | `/api/posts/<id>/like/` | like / unlike |
| POST/DELETE | `/api/posts/<id>/save/` | save / unsave |
| GET | `/api/posts/saved/` | my saved posts |
| existing | comments + CRUD | unchanged, privacy-gated on create |

### Privacy enforcement (your requested feature)
When liking a post, the **post author's** `allow_likes_from` is checked:
- `everyone` → allowed
- `friends` → allowed only if liker & author are mutual follows
- `nobody` → blocked (403)

Same logic for `allow_comments_from` on comment creation. Liking/commenting on your own post is always allowed. Enforced in views + permission classes.

## 4. Frontend — Instagram-style Streamlit UI (multi-file)

**Layout** (dark theme preserved):
- **Left sidebar nav**: Home · Explore · Notifications · Profile · Settings (+ login/register/logout + create-post form).
- **Top friends bar** (Home): horizontal row of avatar circles for people you follow/mutual friends — click to open their profile (your requested "friends on top" like the screenshot).
- **Center single-column feed** of IG-style post cards:
  - Header row: avatar + username + follow/unfollow (or Edit/Delete if it's yours)
  - Content body (styled text box)
  - Action row: ❤️ Like (count) · 💬 Comment · 🔖 Save
  - Expandable comments
- **Pages**: Home (feed), Explore (search users + all posts + suggested), Profile (any user's posts + stats + followers/following + mutual friends + Follow button), Notifications (with unread badges), Settings (edit bio + privacy dropdowns for likes/comments).

Avatars = colored circle with initials (generated client-side; consistent per username) since there are no image uploads.

**Routing**: `st.session_state` holds `current_page` + `viewing_user_id`; `frontend/app.py` renders the selected page. Run command stays `streamlit run frontend_app.py` (thin launcher imports `frontend.app`).

## 5. R&D — other functionalities

**Included now:** likes, follow/friends, mutual friends, privacy settings, profiles, explore/discover, notifications, saved/bookmarks, personalized feed, suggested users.

**Recommended for later** (out of scope this build): photo/image uploads, Stories (24h), Direct Messages, hashtags & tag search, likes on comments / nested replies, post sharing/reposts, email verification, rate limiting, real-time (WebSockets/Channels).

## 6. Implementation & verification steps
1. Create `accounts` app (`python manage.py startapp accounts`), register in `settings.INSTALLED_APPS`, add signal wiring.
2. Add `Like` + `SavedPost` models to `blog`, add `Notification`/`Profile`/`Follow` to `accounts`.
3. Write serializers, views, URLs, permissions.
4. `python manage.py makemigrations` → `python manage.py migrate` (additive, non-destructive).
5. Rebuild frontend into the `frontend/` package + launcher.
6. Verify: run Django server + Streamlit, smoke-test register → login → create post → like → follow → check privacy → notifications → save → explore.
7. Keep existing tests passing; add a few targeted tests for like/follow/privacy.

**Backwards compatible:** existing `/api/posts/`, `/api/comments/`, and auth endpoints keep working — only enriched.
